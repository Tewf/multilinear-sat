# Literature review: SAT by multilinear relaxation

Method note: built from six internal, unpublished reviews written on 2026-08-26 (each source fetched and quoted, with its own "not found" markers), the design notes and the measured results of the PyTorch prototype that preceded this repository, plus direct verification on 2026-08-27/28 of two GitHub repositories (`gh repo view`) and about twenty citations (DBLP's and arXiv's public APIs, Crossref). Every claim below is traceable to one of those; anything neither the sources nor a fetch could confirm is marked "not verified" or "not found", following the source reviews' own convention.

## 1. The problem and its names

A SAT or MAX-SAT instance can be relaxed by letting each Boolean variable take a probability p_i in [0,1] (equivalently a value in [-1,1] under a +/-1 encoding). The expected number of clauses satisfied under independent coin flips at these probabilities is a polynomial in p that is affine in each p_i separately: a multilinear polynomial, equal to its own Fourier or Walsh expansion over {-1,1}^n. The field calls this the multilinear extension of the underlying Boolean function (Williamson and Shmoys use it for derandomization by conditional expectations, without ever using the word "multilinear", ch. 5), and searching it with gradients is continuous local search (CLS), as distinct from stochastic local search (SLS: WalkSAT, probSAT, CCAnr, which flip discrete bits) and CDCL (which branches and learns clauses). FourierSAT and its successors write the same polynomial as a sum of Fourier or Walsh characters, so "Fourier expansion" and "multilinear extension" name the same object.

This repository sits in the continuous local search line: it evaluates the multilinear energy of each clause and runs batched projected gradient descent from many random starts on the GPU. This directly executes the theorem in section 4 that a multilinear polynomial on the cube attains its maximum at a vertex, so the relaxation's exact optimum is exact MAX-SAT and the gradient only supplies a direction toward it. On top of that it adds Luby restarts (the proven-optimal universal restart schedule of Luby, Sinclair and Zuckerman) to decide how long to run a batch before reseeding, and a focused noise kick, a WalkSAT-style perturbation restricted to variables in currently violated clauses but applied without a discrete choice, as the escape move for the saddle-dominated interior described below. Output is certificate-checked: since a claimed solution must land on the {-1,1}^n vertex, rounding with sign() and evaluating all m clauses is an O(m) exact certificate, cheaper than a general continuous-root certificate (Smale's alpha-theory, Smale 1986) for this constrained case.

## 2. The continuous line

**FourierSAT** (Kyrillidis, Shrivastava, Vardi, Zhang, AAAI 2020, arXiv:1912.01032) converts Boolean constraints to multilinear/Fourier polynomials and its Algorithm 1 is projected gradient descent, first order, with a Hessian-based saddle-escape subroutine (`useHessian`, `DecInnerSaddle`) for when it stalls. Its own reported experiments do not run Algorithm 1 as designed: the paper says it "compared available algorithms" for non-convex constrained optimization and chose SciPy's SLSQP, a quasi-Newton method, with no ablation table shown. Code is public and was verified via `gh repo view`: `vardigroup/FourierSAT`, Python, MIT license. It beats WalkSAT on cardinality and parity-learning encodings and is roughly tied with CryptoMiniSAT on some hybrid or easy cases; it has no clause learning, propagation, or restarts, and is not integrated with CDCL.

**GradSAT** ("On Continuous Local BDD-Based Search for Hybrid SAT Solving", Kyrillidis, Vardi, Zhang, AAAI 2021, arXiv:2012.07983) is CPU only, not GPU, running a portfolio of four optimizers (SLSQP, MMA, CG, BFGS) on up to sixteen cores. Its own four-way ablation (Table 4) shows BFGS alone is the best single optimizer (0.954 average score, 293 wins) ahead of CG (0.949, 234) and SLSQP (0.937, 206), even though the paper states elsewhere that "Hessian-based algorithms... are usually too expensive to use" in practice. The full sixteen-core portfolio (0.970, 465 wins) beats WalkSAT (0.917, 124), FourierSAT (0.908, 108), the mixing method (0.892, 121), and Loandra (0.874, 41) on its own MaxSAT table. Code is not public, supplemental material only.

**FastFourierSAT** ("Massively Parallel Continuous Local Search for Hybrid SAT Solving on GPUs", Cen, Zhang, Fong, AAAI 2025 Oral, DOI 10.1609/aaai.v39i11.33211, arXiv:2308.15020) is the real GPU implementation of this line: an FFT-based parallel Walsh-coefficient computation tested on an A100, reporting a 100x-plus gradient speedup over CPU. It solves every instance of a 90k-variable cardinality benchmark and every parity-with-error instance tested, and wins weighted Max-Cut (323 best solutions against a virtual-best-solver's 83) over NuWLS, NuWLS-c, SATLike, SATLike-ck and TT-Open-WBO; it was not tested on plain random 3-CNF. Correction to the 2026-08-26 review: its code is public. `github.com/seeder-research/FastFourierSAT` was verified via `gh repo view` on 2026-08-27/28 (Python, JAX + JAXopt, CC0-1.0 license), and its own README, fetched directly, confirms JAX/JAXopt/CUDA-12 as the install path and describes the repository as "the vectorized version of FourierSAT which enables GPU". No native (C++/CUDA) implementation of this line was found: `gh search repos` returned zero repositories on six phrasings tried across 2026-08-26 and 2026-08-28, including "multilinear extension SAT", "GPU SAT solver gradient", and "Fourier expansion SAT CUDA". This is "not found", not "does not exist".

**The mixing method** ("The Mixing method: low-rank coordinate descent for semidefinite programming with diagonal constraints", Wang, Chang, Kolter, arXiv:1706.00476) is Burer-Monteiro low-rank coordinate descent for diagonally-constrained SDPs, applied to a MAX-SAT SDP relaxation; 0.978 average approximation ratio on MaxSAT-2016 complete-track instances, but it scores below WalkSAT on GradSAT's own comparison table (0.892 against 0.917). Code: `locuslab/mixing`.

**UniSAT** ("Global Optimization for Satisfiability (SAT) Problem", Jun Gu, IEEE TKDE 6(3):361-381, 1994) converts SAT to unconstrained global minimization and applies coordinate descent, not Newton-type search: GradSAT's own text corrects this framing explicitly. It solves only relatively easy random CNF instances and offers no rounding or convergence guarantee; Gu's original text was unreachable this session, paywalled everywhere tried.

**Simulated bifurcation on higher-order costs** ("Simulated bifurcation for higher-order cost functions", Kanao and Goto, Applied Physics Express 16:014501, 2023, arXiv:2211.09296) extends SB from quadratic (Ising) to cubic and higher cost functions. Full text tests it on one 3-regular 3-XORSAT instance against lower-order SB and simulated annealing; no SAT-competition or MaxSAT-Evaluation comparison and no test against probSAT, WalkSAT, CCAnr or SATLike was found.

## 3. Discrete baselines this repository measures against

- **WalkSAT** ("Noise Strategies for Improving Local Search", Selman, Kautz, Cohen, AAAI 1994): the original noise-based random-walk local search, ancestor of every SLS solver below and of this repository's noise kick.
- **probSAT** ("Choosing Probability Distributions for Stochastic Local Search and the Role of Make versus Break", Balint and Schoning, SAT 2012): a break/make-probability-driven variant, the unbeaten baseline on SATLIB uniform random 3-SAT (`adrianopolus/probSAT`).
- **CCAnr** (Cai, Luo, Su, SAT 2015): configuration-checking local search, the standard non-random and structured-instance SLS baseline (`shaowei-cai-group/CCAnr`).
- **CaDiCaL / Kissat** (Biere, `arminbiere/cadical`, `arminbiere/kissat`): competition CDCL. Kissat already runs a WalkSAT-style rephasing walk internally (`kissat_walk()` in `src/rephase.c`, read directly by the source review), scheduled through phases `{best, walking, inverted, best, walking, original}`, so beating "CDCL" here means beating CDCL plus discrete local search, not plain CDCL.

## 4. The theorems that frame the method

**Vertex maximum.** A multilinear polynomial is affine in each variable separately, so on the box [0,1]^n or [-1,1]^n its maximum is attained at a vertex (the derandomization-by-conditional-expectations argument in Williamson and Shmoys, ch. 5). The relaxation's global optimum is therefore exact MAX-SAT: relaxing does not make the target easier, it only supplies a gradient to follow toward that same vertex.

**Every interior critical point is a saddle.** FourierSAT's Lemma 3, confirmed verbatim: "Every critical point (where all the first derivatives are zero) of a non-constant multilinear polynomial is a saddle point." Its Example 3 (F = x1 x2 x3 x4) exhibits a degenerate saddle where gradient and Hessian both vanish, so not every saddle is strict. The paper's own Future Directions section states that the strict-saddle assumption needed by perturbed-gradient-descent escaping-saddle theorems (Ge, Huang, Jin, Yuan 2015; Jin, Ge, Netrapalli, Kakade, Jordan 2017) "is not valid in our case"; applying that theory to SAT is unattempted, open, not refuted.

**Lower bounds: nothing here can certify UNSAT.** The 7/8 approximation ratio for MAX-3-SAT (Karloff and Zwick's SDP algorithm, FOCS 1997) is tight: Hastad (STOC 1997 / J.ACM 2001) proves that 7/8 + eps is NP-hard, so no convex relaxation closes that integrality gap. Separately, refuting a random 3-CNF near the satisfiability threshold needs Polynomial Calculus, hence Groebner-basis, refutation degree Omega(n) with high probability (Ben-Sasson and Impagliazzo, FOCS 1999 / Computational Complexity 2010), and the analogous Lasserre/SoS hierarchy needs level linear in n (Schoenebeck, FOCS 2008). Any method that only multiplies and linearly combines constraints, including a Gaussian-elimination-style reduction of the multilinear system, inherits this bound: this repository's certificate checks SAT, it never attempts to certify UNSAT.

**Overlap-gap-property results, upper bounds on which algorithms can work, asymptotic in k.** Bresler and Huang ("The Algorithmic Phase Transition of Random k-SAT for Low Degree Polynomials", arXiv:2106.02129) show low-degree polynomial algorithms, message passing, and local algorithms on the factor graph fail above a density threshold; Kizildag ("Sharp Thresholds for the Overlap Gap Property: Ising p-Spin Glass and Random k-SAT", arXiv:2309.09913) proves a sharp OGP threshold for a broad class of input-stable algorithms. Both results are stated as k grows large; neither is a proven statement at k = 3, and whether gradient-based continuous local search is "stable" in the OGP sense at k = 3 is inference here, not a cited result.

**Proven upper bounds on discrete algorithms that do not transfer to continuous dynamics.** Schoning's randomized local search gives a Las Vegas 3-SAT algorithm with expected running time (4/3)^n, about 1.334^n (FOCS 1999). PPSZ (Paturi, Pudlak, Saks, Zane, FOCS 1998 / J.ACM 2005) improves this to roughly 1.307^n by combinatorial case analysis combined with limited resolution. Both are proven upper bounds on the worst-case running time of specific discrete algorithms with a particular combinatorial structure (bounded-radius search, k-SAT resolution); no source in this review connects either bound to the basin of attraction of gradient or quasi-Newton dynamics on the multilinear relaxation. One qualification (2026-08-29): Ercsey-Ravasz and Toroczkai claim, by analytical arguments and simulations rather than a theorem, that their continuous-time system finds solutions in polynomial continuous time at the price of exponential fluctuations of its energy; on the discrete side Istrate et al. bound WalkSAT's expected time on satisfiable k-XORSAT, and Lorenz and Wörz show Schöning's run length is approximately Johnson SB with restarts helping the long tail (`fft-walksat-las-vegas/references.bib`). Separately, no paper was found, after several rephrasings against arXiv full text, measuring the fraction of random starts that reach a satisfying assignment under gradient or Newton dynamics on random 3-SAT. The closest verified anchor is Ercsey-Ravasz and Toroczkai's single deterministic continuous-time dynamical system (Nature Physics 7:966-970, 2011), whose basins turn fractal above the constraint-density threshold, a different question (one flow's basin geometry, not restart statistics) from what this repository's batched multi-start method needs.

**Restarts.** Luby, Sinclair and Zuckerman's universal restart schedule (Inf. Process. Lett. 47(4):173-180, 1993) is the restart strategy provably optimal up to a constant factor when the run-length distribution of the underlying randomized algorithm is unknown; this repository uses it to schedule reseeding of the GPU batch. No continuous-optimization analogue of a restart schedule specific to this relaxation was found in the reviewed literature; on 2026-08-29 neither FourierSAT's nor FastFourierSAT's full text contained the string "Luby" or "Las Vegas" (grep, 0 hits each; `fft-walksat-las-vegas/4-positioning.md`).

## 5. Ensemble and decimation (related work, not this repository's method)

Survey propagation (Mezard, Parisi, Zecchina, "Analytic and Algorithmic Solution of Random Satisfiability Problems", Science 297:812-815, 2002) computes marginals on the factor graph by the cavity method. SP-guided decimation, fix the most-biased variable by survey propagation, resimplify, repeat, solves random 3-SAT up to about alpha = 4.21 to 4.24 but "does not seem to converge" up to the threshold alpha_c ~ 4.267 (Braunstein, Mezard, Zecchina, Random Struct. Algorithms 27:201-226, 2005), attributed to the clustering transition.

**SP reinforcement** ("Survey-propagation decimation through distributed local computations", Chavas, Furtlehner, Mezard, Zecchina, J. Stat. Mech. 2005 P11016) replaces hard decimation with a growing external field per variable, realigned each sweep with the variable's local bias, reading off a solution once every variable polarizes in one continuous run. At N = 1e5, alpha = 4.24, it needs about 600 sweeps against hard decimation's 7460, roughly a 5x wall-clock speedup with better asymptotic scaling. This is the closest published precedent for a genuinely continuous decimation analogue, and the discrete-vs-continuous comparison is head to head on the same instance.

**Backbone-guided local search** ("Backbone Guided Local Search for Maximum Satisfiability", Zhang, Rangan, Looks, IJCAI 2003) is the discrete analogue: pool WalkSAT's local optima, compute a per-literal pseudo-backbone frequency, bias remaining tries. It reports about 30% average improvement on hard SATLIB instances (up to 96.93%) but up to 10% worse than plain WalkSAT on symmetric graph-coloring instances, so ensemble-derived biasing is not uniformly helpful.

**Learned initial assignments and decimators, stated as related work.** NLocalSAT ("NLocalSAT: Boosting Local Search with Solution Prediction", Zhang et al., IJCAI 2020, arXiv:2001.09398) trains a network to predict a good initial assignment and seeds five unmodified SLS solvers (CCAnr, Sparrow, CPSparrow, YalSAT, probSAT) with it, reporting 27% to 62% improvement on SAT Competition 2018's random track; only the seed changes, not the move rule. PDP ("PDP: A General Neural Framework for Learning Constraint Satisfaction Solvers", Amizadeh, Matusevych, Weimer, ICML 2019, arXiv:1903.01969) trains a GRU decimator end to end by backpropagation on unlabeled random CNF, beating its own SP and Reinforce baselines and tying Glucose only under a 3-second timeout, losing once the timeout is lifted. Both belong to the cross-instance learned-prior branch that this repository's own design notes keep separate from the main continuous-relaxation line, opened only once the main line has its own numbers.

## 6. Positioning

**What is public.** Two Python implementations exist in this line: `vardigroup/FourierSAT` (MIT license, CPU, PGD plus a Hessian saddle-escape routine) and `seeder-research/FastFourierSAT` (CC0-1.0, JAX + JAXopt, GPU via CUDA-enabled JAX, the vectorized successor of FourierSAT). Both license and language were independently verified with `gh repo view` on 2026-08-27/28. GradSAT's code is not public. No native (C++/CUDA) implementation of the multilinear-relaxation line was found by `gh search repos` across six phrasings tried on 2026-08-26 and 2026-08-28: not found, not "does not exist".

**What this repository adds.** A native, embeddable implementation (C++/CUDA with a CPU backend, for portability and for testing without a GPU) of the same multilinear/Fourier objective, batched projected gradient descent with many parallel random starts, Luby restarts to schedule reseeding, a focused-noise kick restricted to violated clauses as the escape move for the saddle-dominated interior described in section 4, a test suite, and an O(m) certificate check on every reported SAT answer. As far as their papers and READMEs state, neither public repository nor GradSAT combines a Luby restart schedule, a native GPU kernel and a CPU fallback in one package; that combination, plus a head-to-head benchmark against probSAT and CaDiCaL published whatever it shows, is this repository's contribution.

**What it does not claim.** No win on plain uniform random 3-SAT is claimed. The prototype's own benchmark (`prototype/results.md`) lost to both probSAT and CaDiCaL there: both solved essentially every satisfiable instance tested (n = 200 to 1000, ratio 4.0 to 4.26) in well under a second, while the plain-PGD prototype's solve rate collapsed as n grew, since gradients of already-satisfied clauses vanish near the cube boundary and the last few violated clauses need a coordinated discrete move that pure gradient descent has no mechanism for. This matches the reviewed literature's finding that no published GPU relaxation beats probSAT or CDCL on plain random 3-SAT. Where continuous methods are reported to win (cardinality constraints, XOR or parity with error, and weighted Max-Cut, all from FastFourierSAT's own benchmarks), v0.1 of this repository does not support those encodings; closing that gap is future work, not a v0.1 claim.
